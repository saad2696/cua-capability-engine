1 · The legacy appChrome1:00
localhost:4100 → sign in demo / demo → type 10042 → Search. Land on the Member Detail page and pause there.
"This is the kind of core banking UI that still runs in production and that nobody is going to rewrite. Framesets, table layouts, no API, no test ids. The value I want — this savings balance — is in an unlabelled table cell. Every design decision after this follows from that constraint."

Optional, five seconds: right-click → View Source, scroll once, close it. It makes the "the model never sees raw HTML" line in shot 2 land harder.

2 · Discovery — learn G1Terminal1:30
pnpm cua discover \
  --goal "Look up member {memberId} and read the current balance of their Savings account." \
  --url http://localhost:4100/ --capability-id member-savings-balance --param memberId=10042
"I give it a goal in plain English and a URL. It signs in, searches, and reads the balance — about eight model calls, seven cents."

While it runs, say the two things that matter:

"The model never sees raw HTML. It sees an accessibility tree flattened across the frames, plus a screenshot with every interactive element numbered — which is roughly what a human operator perceives. And {memberId} is a parameter, while the password is a reference to an environment variable. The literal value is substituted at the browser after the model has decided, so a credential never reaches the model, the transcript, or the artifact."
3 · The artifactTerminal0:45
pnpm cua artifact summary artifacts/member-savings-balance@1.json
The step list with <secret TARGET_PASSWORD> and {memberId} visible as references.
"That is the output — and it is not a transcript. It is a typed, versioned contract: declared inputs and outputs, every step with its locator fallbacks, what each step expects to be true afterwards, and a catalog of the conditions this flow knows how to handle. Someone can review and approve this without reading a log. That is the whole point."
4 · Refusal → approve → replayBoth1:30

4a — terminal. Lead with the refusal. It is the beat people remember.

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=10042
#   → FAILURE ARTIFACT_NOT_APPROVED   (0 steps, 3ms)
"A model worked this out once. That does not make it allowed to run unattended. Notice it refused in three milliseconds without even opening a browser."

4b — Chrome. Console → Capabilities → member-savings-balance@2 → Approve for unattended replay.

Before clicking approve, scroll the contract once: inputs, outputs, secrets, origins, and a step showing its fallbacks: label → css → visual.
"This is the review surface. Approval is a human decision made once, here, rather than on every run."

4c — terminal.

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=10042
#   → SUCCESS  {"savingsBalance":{"amount":1234.56,"currency":"USD"}}   ~2s

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=10077
#   → SUCCESS  $8,900.04
"Two seconds, no model, no API cost, and the same answer every time. The second member proves the parameter is real rather than baked into the recording."
5 · Three kinds of wrongTerminal2:00

Run all three, then talk. Read the exit codes aloud — that is the shot.

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=99999
#   → BUSINESS_OUTCOME MEMBER_NOT_FOUND            exit 0

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=10042 --fault session_expired
#   → SUCCESS, recovered via the login prelude     exit 0

pnpm cua replay artifacts/member-savings-balance@2.json --param memberId=10042 --fault session_expired:sticky
#   → FAILURE RECOVERY_LOOP                        exit 2
"Three different kinds of wrong. 'No such member' is an answer, not an error — the automation worked perfectly, so exit zero and the caller gets a typed business outcome. If that paged somebody, people would start ignoring the alerts. A session expiry is recoverable, so it re-runs the login and carries on, and the caller never learns it happened. The same expiry that never clears is bounded after two attempts and reported as a failure. A caller can branch on these without parsing a log."
Then: cat evidence/replay-g1-recovery-loop/failure-*.md — expected state, observed state, suggested next action.
"Every failure carries a bundle like this, with screenshots and an accessibility snapshot beside it."

The most important shot in the video. Do not rush it.

Pace must be Watchable. At full speed the run finishes before the live viewport draws a single frame, and the live view is the most convincing thing in the demo.

Press Replay.

6b — it stops by itself. Wait. Do not touch anything.

Banner: UNKNOWN_DIALOG: alert "Core banking link unavailable (ERR-7731)" · state paused · viewport labelled "nobody is driving" · a Waiting badge appears in the nav.
"It stopped on its own. That dialog is not in this capability's outcome catalog, so it refuses to touch it. An automation that dismisses dialogs it does not recognise is an automation that will eventually dismiss something expensive."

The fault fires during sign-in, not at the search — the dialog attaches to the first click or focus. That is normal; don't be thrown by it.

6c — take over. Click Take control.

State → human control; badge → "you are driving"; Accept / Dismiss buttons appear over the live frame.
"Now I am driving the automation's own browser. Not a screenshot, not a copy — the same session, same cookies, same frames."

Click Dismiss. The badge turns to LIVE and you see the sign-in form.

6d — hand back. Click Hand back (mode: Retry the step). Wait for it to finish.

Header: completed · success. Replay panel: 7 steps, balance $1,234.56.
"Seven steps. An uninterrupted run of this capability is also seven steps — so it resumed the step it stopped at, inside the session it paused in. It did not restart the browser, and the page it carried on from is the one my own clicks left behind."

6e — click Waiting in the nav.

resolved · replay failure · same · by operator-1
"And the handover is in the audit trail: who claimed it, what they decided, when."

7b — press Discover and say nothing for a few seconds. Watch the right-hand panel, Artifact taking shape.

The live viewport signs in and searches; the panel fills in step by step, and an Outputs entry appears: branch = "Main Street" via cellRightOfLabel.
"That panel is the recipe being written as it works. Both values come from a different table than the balance did, and it has worked out a re-readable anchor for each — 'the cell to the right of the label Branch'. That anchor is what makes the replay deterministic."

Takes ~25 seconds, 8 model calls, about $0.07. The run ends completed and the Evidence panel lists artifact.json alongside the screenshots.

7c — terminal. Prove the thing it just learned actually runs.

#   → {"branch":"Main Street","memberSince":"2014-03-11"}   ~2.5s

"Twenty-five seconds to learn it, two and a half to run it, and it generalises to a member it was never shown. That is the whole thesis: the expensive, non-deterministic part happens once."
8 · The flow that commitsBoth2:30
"Everything so far only read data. This one opens an account."

8a — terminal. Show the evidence of the real run rather than running it live (a live run here is 40 seconds of dead air).

cat evidence/discovery-g2-open-subaccount/run.json
python3 -m json.tool evidence/discovery-g2-open-subaccount/interventions.json | grep -E '"reason"|"status"|"resolvedBy"'
15 steps, 15 calls, $0.14 — and three interventions.
"It stopped three times. Two were the policy: the button whose label matches the irreversible list, and the browser's own confirm dialog — which is the step that actually opens the account, so it is treated as a separate decision. The first one the model raised by itself, before any rule fired: it reached the review screen and asked for a human on its own initiative."

8b — Chrome. Capabilities → member-open-subaccount@1, scroll to steps 7 and 8.

Both tagged risky · point of no return, with the model's recorded reasoning underneath.

8c — terminal. The closing pair. Same artifact, same parameters.

pnpm cua replay artifacts/member-open-subaccount@1.json --param memberId=10042
#   → SUCCESS  {"confirmationNumber":"CU-7000xx"}  side effects: committed   exit 0

pnpm cua replay artifacts/member-open-subaccount@1.json --param memberId=10042 --risky block
#   → FAILURE POLICY_VIOLATION                     side effects: none        exit 2
"Same capability, same inputs, one line of policy different — and the difference is whether an account gets opened at all. The guardrail belongs to the deployment, not to the recorded flow."
Optional: refresh the member page in the bank UI to show the new sub-account.
"And the confirmation number changes on every run, because every run really does open an account. That is what 'committed' means here."
9 · Safety and evidenceTerminal1:00
pnpm cua doctor
"The secret check asks git, not .gitignore. Those two disagree exactly when a file was staged before the ignore rule was written — which is the case that actually leaks a key — and deleting it later does not help, because the history keeps it."
cat policy.yaml        # scroll slowly
ls evidence/
"Everything the engine may do is this one validated file, loaded by every entry point. Four layers enforce it: the model's decision, the surface boundary, the network, and a pre-flight check on the artifact. A human who takes control is not blocked by it — they are recorded as an override, because refusing them would disable escalation exactly when it is needed."

Finish on the limit, out loud. It is a strength, not a weakness.

"And the honest part: screenshots are not masked. They render whatever was on screen, member IDs included. The structured evidence is redacted and there is a test that walks every file a run writes — but a grep cannot see inside a PNG, so the schema pins that flag to false and it is written down in the README. Everything here is synthetic data in an app I wrote."
10 · Close—0:30
"So: an LLM works the task out once, under policy, with a human for anything irreversible. What it learned becomes a typed artifact that a person approves — and that artifact runs in two seconds with no model and no API cost. When the application does something it has not seen, it stops and hands a person the same live browser rather than guessing. The model is a compiler, not a runtime."

If you want one more sentence, make it the honest one — it lands better than a feature:

"The most useful thing I found building this was that the flow that commits money was impossible for the system to complete, while the entire test suite was green. It only showed up when I drove the real application to its point of no return."

SymptomCause and fix

Confirmation number is not CU-700001Expected — it climbs within a session. Restarting the target app resets it. Say so; it proves the run committed.
