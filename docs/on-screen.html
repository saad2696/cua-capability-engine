Computer-Use Automation System
Problem · How · Capabilities · Error handling · Human in the loop · Safety · Beyond the brief · Limits

An LLM learns the task once.
The recording runs it forever.

A model works out how to do a job in a legacy banking UI, once. What it learned becomes a typed, versioned capability artifact — which then replays deterministically, in about two seconds, with no model in the loop. Anything irreversible, or anything it has not seen before, stops and hands a person the same live browser session.

The problemThree things you want, in tension

Flexibility

A UI nobody documented. No API, no test ids, framesets and table layouts.

→ argues for an LLM driving live

Determinism

Same input, same result, every time, auditable by someone who wasn't there.

→ argues against a model anywhere near the hot path

Safety

Some actions move money and cannot be undone.

→ argues for a human, but a human on every run is not automation

The decision that resolves it: the model is a compiler, not a runtime.

Error handlingEvery run ends in one of four shapes

OutcomeExitMeaning · who acts
success0Done. Typed outputs returned.
business_outcome0The application legitimately said no — no such member, not authorised. The automation worked. Nobody is paged.
failure2Could not proceed. Always carries a bundle: narrative, screenshots, a11y snapshot, page text.
escalated3A human is needed.

Recovered silently, and bounded

SESSION_EXPIRED re-runs the login prelude · SERVER_ERROR reloads · a declared dialog is dismissed · slowness is tolerated and flagged.

RECOVERY_LOOP is the guard: the same condition twice at the same step stops the run.

Refused before a browser opens

INVALID_INPUT · MISSING_SECRET · ARTIFACT_NOT_APPROVED · POLICY_VIOLATION.

A bad call costs milliseconds, and stepsRun: 0 proves nothing touched the application.

Human in the loopTake over the same live session

It stops by itself

A risky step, an undeclared dialog, an unknown screen. It never guesses.

You drive its browser

Same cookies, same frames, same scroll position — streamed over a websocket, your clicks forwarded back.

It resumes mid-flow

A handover run finishes in 7 steps — the same as an uninterrupted one. It resumed; it did not restart.

Exactly one controller holds a lease at a time. Acting without one is a logged CONTROL_VIOLATION. Time parked in an intervention does not count against the run budget.

SafetyOne policy file, four gates

LayerWhy the one above it is not enough
1 · Decision—
2 · Surface boundaryReplay has no model, so layer 1 never runs on the path that runs most often.
3 · NetworkA redirect or injected asset moves the session without any engine code asking.
4 · Pre-flightAn artifact travels between environments; its policy must be a subset of the one in force.

Everything the engine may do lives in one validated policy.yaml. Unknown keys are rejected — a misspelled control that silently enforces nothing is worse than a startup error. A human who takes control is not blocked; they are recorded as policy_override.

Beyond the briefThings I built that weren't asked for

Because the interesting behaviour is failure

A mock core banking system, with fault injection

Framesets, table layouts, no test ids, a native confirm() at the point of no return — and eight faults armable inside a running browser, so recovery is demonstrated rather than described.

Business outcome ≠ failure

"No such member" is an answer, not an error: exit 0 with a typed code. If that paged someone at 3am, people would start ignoring the alerts.

Because an artifact has to survive the UI changing

Ranked locator fallbacks

role+name → css → visual position, each with the recorder's rationale. XPath rejected: it encodes exactly what a redesign changes.

Drift as early warning

Matching on a fallback emits drift; a control that moved emits visual_drift. Neither fails the run.

Screen signatures

A step asserts URL + N of M landmarks before acting, so it refuses the wrong screen instead of clicking blindly.

Because someone has to trust it later

Evidence for every run

events.jsonl, before/after screenshots, Playwright trace, and a failure bundle with a narrative naming expected vs observed state.

Approval gate with provenance

Unattended replay refuses a draft. Approving records who and when.

cua doctor

Asks git, not .gitignore, whether a secret is tracked — and whether one was ever committed, because deleting it later doesn't help.

Because the operator is part of the system

Live viewport, not screenshots

Frames streamed from the automation's own browser, with clicks and keystrokes forwarded back.

Console writes capabilities too

Type a goal in plain English; parameters are read out of the {braces} you type.

Optional review of a "no"

A business outcome can pause for a human instead of returning — off by default, because a batch must not stall on a legitimate no.

Findings that only appear when you run the real thing

  • A whole goal was impossible, with the suite green. The app takes its final approval with a native confirm(); the model had no tool that could answer one. Adding it exposed five further defects, each producing a plausible wrong answer rather than a crash.
  • A monitoring signal that fired on a page that had not changed. Visual drift used box overlap; legacy buttons are ~37×14px and it collapsed at that scale. Found by reading the evidence of a passing run.
  • An anchor that only worked for one member. The model anchored a value to an account nickname. It read fine for Alex Sample and failed on the next member — caught by replay, by name, in two seconds.
  • Three redaction leaks, the last fixed by a test that walks every file a run writes rather than the ones someone remembered.

Honest limitsWhat it does not do

Screenshots are not masked

They render whatever was on screen. Structured evidence is redacted and tested — but a grep cannot see inside a PNG, so the schema pins that flag to false rather than letting a deployment claim otherwise.

One operator, loopback only

The console has no authentication. approvedBy is already in the record for the identity that would replace the assumption.

Multi-tenant is designed, not built

An artifact carries the origins it was recorded against and pre-flight refuses anything else — so a different origin is already a different tenant.

No arithmetic in replay

Every output must be re-readable from the page, so the engine reads a total the application shows rather than summing rows itself. A derive step is the next thing I'd build.
